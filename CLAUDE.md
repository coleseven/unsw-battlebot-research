- Bots must keep state on `self` only (the arena gives each dragon fresh module copies; the judge gives each its own process).
- Judge budget: 100M CPU points per dragon-turn, Python 3.13 + NumPy only. Verify heavy changes with `unswbc run ... --sandbox`.
- Before claiming an improvement, compare against the latest version and distinct sparring opponents on the full official suite; require a benefit that is robust across maps and opponents. Do not treat duplicate deterministic seed runs or their narrow CI as independent evidence.
- For **every bot-change evaluation**, including map-specific logic, play both sides on all 15 distinct ranked maps using `bcsim.official_suite.ranked_maps()` (the default in `full_change_test`, `ablate` and `tune`) and `require_coverage()`: the 11 official maps (Default Small, Trophy, Queen Of Spades, Default, Devil, stronghold, Trauma, Schooltime, Big Empty, Arena, Colosseum) plus the 4 ladder maps (Autarky, Prisoners Dilemma, Slithery Fight, Portals). Every map seen in ranked replays (23 names, 26 Sep) is one of these 15 layouts; re-check when new maps appear. Report official and ladder maps separately too. The ranked server currently draws only 10 of them (`official_suite.CURRENT_POOL`, sampled 27 Sep; re-sample public ranked battles before relying on it): judge changes on that pool first, use the rest as a regression guard. Elo counts the fraction of games won per 5-game battle (docs: /docs/elo), and a game is won by elimination, else longest living dragon, then total length (/docs/structure): tune on the `aligned` objective or wins, never total length alone. Small-map diagnostic probes are allowed, but never substitute for the full-suite result.
- Use memory-safe full compute by default: `bcsim.official_suite.DEFAULT_WORKERS` (currently eight workers on this host), `bcsim.guarded.stage` / `bcsim.bounded.run`, and their RAM checks.
